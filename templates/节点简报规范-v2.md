# 节点简报编写规范 v2（PM 必守）

> 目的：让拿到简报的 AI agent **不用摸索仓库**就能开工，并且在**上游状态与代码不符时能立刻发现**。
> 适用范围：`pmctl agent` 生成的 `.pm/<project>/agent/tasks/*.md`。

## 一、v1 的三个实际问题

1. 只给 WHAT（标题 / 验收一句话 / 文件清单），不给 HOW——命令、环境、运行期依赖都要 agent 自己挖。
2. 验收标准不可执行：「两镜像本地构建通过」没有对应命令，agent 只能猜基础镜像和上下文。
3. **上游缺口不可见**：B1 在计划里标 done，代码里却没有 `UI_HOST`；下游 B2 的简报完全看不出来。

## 二、必填小节（缺一即视为不合格简报）

| 小节 | 内容要求 |
|---|---|
| 目标与不在范围内 | 一句话目标；明确列出本节点**不做**什么 |
| 验收标准 | 可判定，不写"应该""基本" |
| **验收命令** | 可直接复制的 shell；每条注明**期望输出特征**（如 `200`、`"ok"`） |
| 涉及文件 | 路径 + **符号名或行号**（如 `scripts/x.ts:518 listen`） |
| 环境前提 | 运行时版本、需要的服务、端口、依赖 |
| 运行期依赖 | 数据/目录/环境变量（如 `fixtures/compliance/`、`var/demo.sqlite`） |
| **上游状态核对** | deps 逐条列：计划状态 vs **代码现状**；不一致必须显式标出并归属 |
| 已知验证命令 | 计划有则填，无则写"计划未给出，需自行核实"（**禁止编造**） |
| 停止条件 / 完成写法 / 报告格式 | 沿用现有 |

## 三、反例与正例（以 B2 为样本）

### 反例：v1 实际产出

```markdown
## 验收标准
两镜像本地构建通过
## 涉及文件
deploy/Dockerfile.ui、deploy/Dockerfile.mcp
## 下一步（给 Agent 执行）
1. 先等 B1 完成；在此之前不要动本节点，避免返工。
```

问题：没有 build 命令；没说基础镜像怎么定；没有提示 **B1 其实没实现**，导致 agent 把"能构建"当成"可用"。

### 正例：v2 应产出

```markdown
## 验收标准
两镜像本地构建通过，且 MCP 容器启动后健康检查可达。

## 验收命令
docker build -f deploy/Dockerfile.mcp -t demo-mcp:local .
docker run --rm -d -p 8790:8790 --name demo-mcp-check demo-mcp:local
sleep 3 && curl -fsS http://127.0.0.1:8790/healthz      # 期望 200
docker build -f deploy/Dockerfile.ui -t demo-ui:local .

## 涉及文件
- `deploy/Dockerfile.ui`、`deploy/Dockerfile.mcp`（新增）
- `scripts/mcp-serve.ts:15` 读取 `MCP_HOST` / `MCP_PORT`
- `scripts/compliance-ui-server.ts:41,518` `UI_PORT` 可配，但 `listen` 仍硬编码 `127.0.0.1`

## 环境前提
Node >= 24；Docker 可用；仓库无原生模块（`store.ts` 用内置 `node:sqlite`）。

## 运行期依赖
`fixtures/compliance/*.json`（两个服务都读）；UI 写 `var/demo.sqlite`（容器内需可写）。

## 上游状态核对
- **B1「UI_HOST 可配置」：计划状态 done，代码未实现** —— `UI_HOST` 在 `scripts/` 下不存在，
  `compliance-ui-server.ts:518` 仍为 `server.listen(PORT, "127.0.0.1")`。
  影响：UI 镜像能构建、能启动，但**外部访问不到**。该缺口归 B1，不计入本节点验收失败。

## 已知验证命令
见上「验收命令」。
```

## 四、生成器落点（已落地）

- `src/facts.mjs`：把计划节点的可选字段 `verify` / `env` / `runtimeDeps` 带进 facts（缺失时为 `null`）。
- `src/agent.mjs`：节点简报渲染段新增「验收命令」「环境前提」「运行期依赖」「上游状态核对」四节；删除原「已知验证命令」（内容被「验收命令」取代）。
- `index.json` 同步携带这三个字段，机器可读读者也能拿到。

## 五、硬性要求

1. **上游 deps 凡「计划 done 但无任何 PR / 提交证据」的，必须在简报里显式标出**（生成器已实现该告警）；发现代码与计划不符时先报告差异，禁止默认它可以开工。
2. 验收命令必须是**可执行**的；写不出就写"计划未给出，需自行核实"，**禁止编造**。
3. 不写"预计 / 应该 / 基本可用"这类无法判定的措辞。

## 六、验证结果（2026-11-24）

- B2 简报现在包含：验收命令（含期望输出）、涉及文件（带符号行号）、环境前提、运行期依赖、上游状态核对。
- 上游核对自动抓出：**B1 计划标 done，但没有任何 PR / 提交证据**。
- `npm test`：818/818 通过。
